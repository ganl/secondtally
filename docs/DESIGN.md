## 一、设计系统

### 色板(深色主题)

| 用途 | 色值 | 用在哪 |
| --- | --- | --- |
| 页面底色 | `#0f172a` | 所有页面背景 |
| 卡片底色 | `#1e293b` | 输入卡片、条目卡、列表项 |
| 分割线 / 轨道 | `#334155` | 进度条底轨、边框 |
| 强调色 | `#6366f1` | 主按钮、FAB、进度条填充 |
| 预警色 | `#f59e0b` | 进度条剩余不足 30%、警告条 |
| 主文字 | `#f8fafc` | 标题、验证码数字 |
| 次文字 | `#94a3b8` | 副标题、提示 |
| 弱文字 | `#64748b` | 占位符、辅助说明 |
| 禁用文字 | `#475569` | 已过期的验证码、分隔符 |

### 字号(rpx,750 设计稿基准)

| 层级 | 值 | 用途 |
| --- | --- | --- |
| 页面主标题 | 40–52 | 首屏大标题 |
| 验证码(列表) | 76 | 6位/8位数字,等宽字体 |
| 条目标题 | 30左右 | 服务名 |
| 正文 | 26 | 描述、说明 |
| 辅助 | 22–24 | 时间戳、占位符 |

### 间距与圆角

- 页面左右留白 `32rpx`
- 卡片圆角 `20–24rpx`,列表项 `16–20rpx`
- 卡片内边距 `40rpx`,列表项 `28–32rpx`
- 列表项之间`24rpx`

## 二、关键设计决策及理由

### 2.1 验证码分隔符做暗色

```
4 7 2 9
↑ ↑
分隔符 `#475569`,数字 `#f8fafc`
```

理由:整串同色会糊成一片难以扫读;分隔符暗化后能快速定位数字边界,
但又不会抢走数字的视觉焦点。

### 2.2 进度条变琥珀色是预警,不是装饰

剩余时间 < 30% 时,进度条填充从 `#6366f1` 转 `#f59e0b`。

理由:作用是**提示该切下一个码了**。TOTP 码在切换瞬间若用户还在读旧码会失败,
预警的价值高于一致性。

### 2.3 过期码变灰但不隐藏

数字变 `#475569`,保留在原位。

理由:隐藏会导致用户以为出 bug。变灰既表达"已失效",又保留"它确实存在过"的信息。

### 2.4 长按直接复制码

点按 → 进详情页;**长按 → 直接复制**。

理由:复制验证码是最高频操作,不该多点一次。进详情页是低频的"看更多信息"。

### 2.5 列表按「常用 / 其他」分组

收藏项沉到顶部,组标题显示数量。

理由:减少滚动距离。条目多时这个收益放大。

### 2.6 创建保险库时把「不可找回」放在最显眼处

琥珀色左边框的提示条,位于表单之上、文案直白。

理由:这是端到端加密的必然结果,不是缺陷。但用户必须**在创建前**知道,
否则创建后才发现会陷入无法挽回的境地。

### 2.7 解锁失败与「用户不存在」返回完全相同的响应

`INVALID_CREDENTIALS` / 「账户或密码错误」,服务端还会执行一次 scrypt 让耗时接近。

理由:防止通过响应差异枚举出哪些账户已注册。UI 上也不做差异化提示。

## 三、页面清单(8 个)

| 页面 | 用途 | 入口 |
| --- | --- | --- |
| `gate` | 门禁:创建 / 解锁 | 启动唯一入口;自动锁定后也回这里 |

| `entry` | 详情:大号码 + 元信息 | 点列表项 |

| `recovery` | 恢复码 | settings |
| `audit` | 使用记录 | 列表页顶栏 |
| `settings` | 同步 / 锁定 / 导入导出 | 列表页顶栏 |

## 五、已知的设计缺陷

**流程问题**:先写了 8 个页面的实现,才谈设计。
这意味着改主色、加页面、调信息层级都必须动代码,
而设计阶段做这些只需改一张图。后续项目应先出设计稿再实现。

**尚未实现的设计**:

- 无浅色 / 深色切换
- 无无障碍标注(`aria` 角色、对比度未系统校验)
- 进度条无刻度,用户无法直观知道"还剩几秒"
- 批量操作(多选删除、导出选中项)未设计
- 小程序端无下拉刷新
